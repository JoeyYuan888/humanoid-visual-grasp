## 3. 当前锁存目标

当前使用：

```text
data/mpc_locked_target_latest_bak.json
```

其中物体 BASE 坐标：

```text
object_base.x = 0.6467 m
object_base.y = -0.0215 m
object_base.z = 0.4093 m
```

今天实测得到的抓取 TCP offset 初版：

```text
offset_x = +0.05 m
offset_y = -0.05 m
offset_z = +0.410 m
```

注意：

```text
offset_z=0.410m 不是手指离塑料袋 41cm。
它表示当前 MPC TCP 参考点相对视觉 object_base 点的 z 偏移。
这个值包含 TCP 定义、手掌姿态、手指几何结构、视觉深度误差。
该 offset 只是今天的临时实测值，还不能作为最终抓取参数。
```

后续换物体位置时，初版目标 TCP 可按下面计算：

```text
target_tcp.x = object_base.x + 0.05
target_tcp.y = object_base.y - 0.05
target_tcp.z = object_base.z + 0.410
```

但这个公式成立的前提是 `object_base` 本身稳定可信。当前塑料袋 bbox/depth 取点可能存在偏差，明天需要优先检查视觉取点策略。

需要区分两个 offset：

```text
1. vision_depth_offset
   作用在 bbox 内，决定从检测框哪个位置取深度点。
   目标：让 object_base 更接近真实塑料袋抓取区域。

2. grasp_tcp_offset
   作用在 object_base 之后，决定 TCP 相对物体点的抓取补偿。
   目标：让手指/手掌落到可抓取位置。
```

当前还不能只调 `grasp_tcp_offset`，因为如果 bbox 取深度点本身偏了，TCP offset 会被迫补偿视觉误差，换物体位置后不稳定。
