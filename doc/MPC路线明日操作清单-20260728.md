# MPC 路线明日操作清单 - 2026-07-28

本文写给继续实机测试时使用。目标是继续 MPC 路线：头部低头/抬头统一使用 MPC neck，视觉检测 plastic bag，检查 bbox 深度取点和抓取点 offset，再用 MPC 执行右臂路径。

当前路线原则：

```text
1. 手臂抓取路径只走 MPC，不再组合其他轨迹路线。
2. 头部低头/复位走 MPC neck；调用 neck_movej 前必须先开启 MPC mode。
3. 路径避障靠 MPC PoseArray 里的完整 pose 约束点。
4. 每个约束点都记录 position + orientation，不能只记录位置再套同一个手掌姿态。
5. 视觉目标先在低头姿态下锁存为 BASE 坐标，后续不要用旧 CSV + 新头部 TF 重新计算。
6. 明天第一步不是直接继续调手臂，而是低头看 bbox 位置、深度取点位置、抓取点位置，并设置视觉取点 offset。
```

## 1. 启动 huimin1.4 rosbridge

在机器人自己的 `huimin1.4` 容器里启动 MPC rosbridge。不要动旧 rosbridge。

```bash
source /opt/ros/noetic/setup.bash
source /workspace/catkin_ws/mpc_ws/devel/setup.bash
roslaunch rosbridge_server rosbridge_websocket.launch port:=9091
```

确认 `mpc_target` 和 `mpc_hardware_interface` 服务类型能被 rosapi 看到：

```bash
rosservice call /rosapi/service_type "service: /wa/points_seq_tracking"
rosservice call /rosapi/service_type "service: /wa/wa_hardware_interface/neck_movej"
```

期望：

```text
type: "mpc_target/PointsSeqTracking"
type: "mpc_hardware_interface/MPCNeckJointMove"
```

如果 neck 服务报 `Unable to load the manifest for package mpc_hardware_interface`，需要把本项目的 `mpc_hardware_interface/` 或 `mpc_hardware_interface_catkin_ready_20260728.zip` 放入机器人容器 `/workspace/catkin_ws/mpc_ws/src/`，重新编译并重启 9091 rosbridge。

注意：`MPCNeckJointMove.srv` 以厂商实际包为准，`t` 是 `float64`，不是旧文档里的 `int32`。如果编译成 `int32 t`，会出现 neck 服务 MD5 mismatch。

```bash
rostopic hz /zj_humanoid/sensor/realsense_head/color/image_raw/compressed
rostopic echo -n 1 /zj_humanoid/sensor/realsense_head/color/camera_info
```

脚本遇到无帧/无目标时，除非显式加 `--skip-neck-home`，仍会继续尝试 MPC neck 抬头复位。

它会自动完成：

```text
1. 开启 MPC mode。
2. MPC /wa/wa_hardware_interface/neck_movej 低头到 [0.0, 0.40]
3. 读取 /zj_humanoid/upperlimb/joint_states，确认 Neck_Y 实际到位
5. 检测 plastic bag
6. 保存 data/grasp_data_*.csv
7. 在低头 HEAD TF 下转换 camera -> HEAD -> BASE
8. 保存 data/mpc_locked_target_latest.json
9. MPC neck_movej 抬头复位到 [0.0, 0.0]
```

说明：除非显式加 `--skip-neck-home`，即使没有检测到 valid 目标或锁存失败，脚本也会先尝试执行 MPC neck 抬头复位，再抛出错误。

如果脚本报 `neck_movej 调用完成但关节未到目标`，先确认 9091 rosbridge 已 source `mpc_hardware_interface`，并确认 MPC mode 已成功开启。

如果脚本报：

```text
service /wa/mpc_target_lock_waist_setting unavailable
```

说明 `/wa/waist_lock_setting` 外层服务存在，但它内部依赖的后端 `/wa/mpc_target_lock_waist_setting` 没启动。先在机器人容器查：

```bash
rosservice list | grep -E "mpc_target_lock_waist_setting|waist_lock"
rosnode list | grep -E "waist|lock|target"
```

这个问题不能靠 PC 端脚本修复，需要确认 MPC target/waist lock 后端节点如何启动，或向厂商确认缺少哪个 launch。

如果只想单独测试 MPC neck，不跑视觉：

```bash
python tools/run_mpc_perception_lock.py --ws-url ws://192.168.20.98:9091 --neck-only --skip-neck-home
```

## 3.1 抓取执行策略：约束段和自由段分开

当前推荐不要把 `0 -> 1 -> 2 -> 3 -> 物体上方 -> 物体` 全部放进同一个 `points_seq_tracking_with_joints` 请求。

原因：

```text
points_seq_tracking_with_joints 的 joint_num/states 是整条请求的关节约束。
如果把物体上方/下降点也放在同一个 with_joints 请求里，MPC 仍会按示教关节状态约束身体。
抓取接近阶段需要允许全身 MPC 自己调整，所以应该切成两段。
```

推荐两段：

```text
第一段：当前点 -> via0 -> via1 -> via2 -> via3
  服务: /wa/points_seq_tracking_with_joints
  目的: 复现示教避障路径，限制身体/手臂姿态

第二段：via3 -> 物体上方 -> 下降接近物体
  服务: /wa/points_seq_tracking
  目的: 抓取阶段放开关节约束，允许全身 MPC 调整
```

第一段 dry-run：

```bash
python tools/run_mpc_visual_grasp_test.py \
  --ws-url ws://192.168.20.98:9091 \
  --use-locked-target data/mpc_locked_target_latest_bak.json \
  --via-file data/mpc_via0_home_right.json \
  --via-file data/mpc_via1_pose_right.json \
  --via-file data/mpc_via2_pose_right.json \
  --via-file data/mpc_via3_pose_right.json \
  --stop-at-last-via \
  --no-auto-lift \
  --use-joints
```

第一段确认路径长度后 execute，把 `--max-motion` 改成 dry-run 输出的累计路径长度略大一点：

```bash
python tools/run_mpc_visual_grasp_test.py \
  --ws-url ws://192.168.20.98:9091 \
  --use-locked-target data/mpc_locked_target_latest_bak.json \
  --via-file data/mpc_via0_home_right.json \
  --via-file data/mpc_via1_pose_right.json \
  --via-file data/mpc_via2_pose_right.json \
  --via-file data/mpc_via3_pose_right.json \
  --stop-at-last-via \
  --no-auto-lift \
  --use-joints \
  --max-motion 1.25 \
  --execute \
  --confirm-target
```

第二段 dry-run：到物体上方，不带 `--use-joints`：

```bash
python tools/run_mpc_visual_grasp_test.py \
  --ws-url ws://192.168.20.98:9091 \
  --use-locked-target data/mpc_locked_target_latest_bak.json
```

第二段如果要包含下降接近，使用“距离锁存物体点上方多少米”来控制。先用保守高度，例如物体上方 10cm：

```bash
python tools/run_mpc_visual_grasp_test.py \
  --ws-url ws://192.168.20.98:9091 \
  --use-locked-target data/mpc_locked_target_latest_bak.json \
  --include-descend \
  --above-object-height 0.10
```

确认后再 execute。实际抓取下降高度表示“末端目标在锁存物体点上方多少米”，后续按夹爪和物体高度逐步从 `0.10 -> 0.06 -> 0.03` 调小，不要第一轮直接压到物体/桌面。

需要抬头时继续使用 MPC neck：

```bash
rosservice call /wa/wa_hardware_interface/mpc_mode_setting "data: true"
rosservice call /wa/wa_hardware_interface/neck_movej "neck_joint: [0.0, 0.0]
t: 4.0"
```

## 9. 开启 MPC，执行完整 via0 -> via1 -> via2 -> via3 复现

机器人/容器终端：

```bash
rosservice call /wa/wa_hardware_interface/mpc_mode_setting "data: true"
```

PC 终端，在上一条 dry-run 命令后追加：

```text
--execute --confirm-target --max-motion N
```

`N` 要大于 dry-run 打印的“完整路径累计长度”，建议留 5-10cm 余量。例如完整路径累计长度是 `0.62 m`，就用 `--max-motion 0.70`。

示例：

```bash
python tools/run_mpc_visual_grasp_test.py \
  --ws-url ws://192.168.20.98:9091 \
  --use-locked-target \
  --via-file data/mpc_via0_home_right.json \
  --via-file data/mpc_via1_pose_right.json \
  --via-file data/mpc_via2_pose_right.json \
  --via-file data/mpc_via3_pose_right.json \
  --stop-at-last-via \
  --no-auto-lift \
  --use-joints \
  --max-motion 0.70 \
  --execute \
  --confirm-target
```

观察：

```text
1. 手臂是否朝 via/目标方向移动。
2. 身体是否没有异常扭曲。
3. 手掌姿态是否按 via0/via1/via2/via3 逐步过渡。
4. 高度是否足够，不碰桌沿。
```

如果仍想保留小步验证，可以临时加：

```bash
--step-distance 0.15 --max-motion 0.15
```

但这只会执行完整路径的前 15cm，不等于复现完整 via0 -> via1 -> via2 -> via3。
